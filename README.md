# C 语言学习系统（考研专业课）

13 个题型环，每环三步：**读讲义 → 做自测 → 写 5 道真题**。讲义是网页，自测和编程题在编译器里跑，自动判分。

两种用法：
- **只看讲义**：打开在线网站（部署方法见第八节），或本地双击 `讲义目录.html`。
- **完整学习**：拉取仓库，用 Visual Studio（或任何支持 CMake 的编辑器）打开，按第二节学。

## 一、第一次准备（只做一次）

1. 拉取仓库：
   ```
   git clone https://github.com/zhuyongzhang000-oss/c-.git
   ```
   以后更新：在仓库文件夹里 `git pull`。
2. 打开 Visual Studio →「文件 → 打开 → 文件夹」→ 选刚拉下来的 `c-` 文件夹，等底部输出窗口显示 CMake 生成完成。
   - 不用 Visual Studio 也行：装好 gcc 和 cmake 后，`cmake -B build && cmake --build build`，可执行文件在 `build/` 里。
3. 在启动项下拉框里选 `ring01_quiz`，按 **Ctrl+F5**，能看到「环01 自测」的输出就说明准备好了。
   - 启动项下拉框在绿色三角 ▶ 旁边。窗口太窄时它会被藏起来，这时把窗口拉宽，或者点工具栏右边的「…」。
   - 下拉框里没有 ring01_quiz：点「项目 → 删除缓存并重新配置」，再等一会。
4. 在资源管理器里双击 `讲义目录.html`，用浏览器打开，这是 13 环讲义的目录。不用联网（联网时字体更好看）。

## 二、每一环怎么学

| 顺序 | 打开的文件 | 怎么打开 | 做什么 |
| --- | --- | --- | --- |
| 1 | `讲义.html` | 浏览器（从 `讲义目录.html` 点进去） | 读讲义，下划线的空先自己想再点开 |
| 2 | `自测.c` | 启动项 `ringNN_quiz` | 猜输出、判断对错，运行后自动判分 |
| 3 | `题1~题5` | 启动项 `ringNN_test` | 写 5 道真题的函数，一次测完 |

### 1. 讲义（讲义.html）

- **5 道真题**（最上面）：每道题有完整题目、要求、思路、对应讲义哪一节；点「完整程序」看能直接运行的参考程序（含 `main`）、易错点、输入和运行结果。程序都用 gcc 编译运行过，运行结果是真实输出。先自己写，再展开对照。
- **开始之前**：把前面学过、这一环又要用的基础再考一遍。想不起来就回到出处那一节。
- **前半「编程题怎么写」**：骨架和 ①–⑧。题文件里写的「卡住先看 讲义 第③节」，就是这里同号的节。
- **后半「细节」**：选择题、读程序题专门考的东西，比如字符常量合不合法、`i++` 和 `++i`、`switch` 穿透、`*p++`。每一节最后是「真题里这样考」，灰色小字是出处。
- 下划线是留给你的空，点一下看答案；每节标题右边的「本节答案」一次揭开这一节；开头的「全部揭开」看全部。红色波浪线是不合法或者容易错的写法。
- 讲义会记住你读到哪：再打开时顶上有「上次读到 …」，目录页会标出上次看的那一环。电脑上按 J / K 跳到下一节 / 上一节，A 全部揭开或盖上；手机上右下角有「目录」和回到顶部。
- 代码块右上角有「复制」，想亲手试就贴到 `草稿/草稿.c` 里，启动项选 `draft` 运行。
- 讲义网页由 `公共/讲义/build.py` 从 `公共/讲义/环NN.txt` 生成，生成时会自动检查所有「看第几节」的引用。5 道真题的题目取自各题文件的文件头，参考代码取自 `答案/题N.c`，`main` 和输入在 `公共/讲义/程序/环NN.txt`；改了这些以后先跑 `python3 公共/讲义/check_progs.py`（编译运行全部 65 个完整程序，更新运行结果），再跑 build.py。要改内容告诉 AI，不要直接改 html。

### 2. 自测（ringNN_quiz）

自测有两种题：

- **猜输出**：大括号里是一段代码，`OUT` 的用法和 `printf` 一样。把你认为会输出的内容写进下一行的引号里：
  ```c
  { int i = 5, a;  a = i++;  OUT("%d %d", a, i); }
  GUESS(1, "5 6");
  ```
  - 空格要写准。换行写成 `\n`。
  - 引号里不填（`""`）算未做，不会揭晓答案。
- **判断**：把 `' '` 改成 `'Y'`（合法 / 说法对）或 `'N'`（不合法 / 说法错）。

运行后，对的显示「对」；错的显示正确答案和一句理由。

凭脑子做，不要回去翻讲义，错了才有用。判断题的答案在 `答案/判断答案.c`，做完再看。

### 3. 编程题（ringNN_test）

1. 打开 `题k_xxx.c`。文件头写了真题原文、你要写什么、卡住先看讲义第几节。
2. 写函数：
   - 有 `return -12345;` 的，删掉这一行再写；
   - 打印类的题，直接在函数里用 `printf` 写。文件开头的 `#include "capture.h"` 别删，测试靠它抓你打印的内容。
3. 选 `ringNN_test`，Ctrl+F5。每题显示一种结果：
   - **通过**
   - **错**：后面是第一组出错的输入、期望和实际。打印类的题会告诉你第几行不一样，`[ ]` 里能看到行首、行尾的空格
   - **未做**：还没写，不算错
4. 有错先自己改；改不出来就把最后一行和那道题的函数发给 AI。
5. 每环的题5 标了【限时】，按考试的感觉限时写。

### 4. 学完一环：让 chat 出题

讲义、自测、5 道题都过了，在 C 的对话里说「测 环NN」：

- chat 会从题库里出这一环的选择题、读程序题。
- 错的题会进回访，以后反复出现。

## 五、遇到问题

| 现象 | 原因 / 办法 |
| --- | --- |
| 运行后停在某个「题k」不动 | 这题有死循环（递归题是没写基例）。关掉黑色窗口，检查循环变量有没有在变 |
| 打印到某个「题k」就退出了，没有最后一行 | 这题让程序崩溃了，常见原因是数组越界、用了 NULL 指针。把这题函数贴给 AI |
| 编译报错，下面有红色错误列表 | 双击错误跳到那一行。看不懂就把错误第一行贴给 AI |
| 自测有黄色警告 | 正常，是故意写的坑 |
| 中文显示成乱码 | 告诉 AI，会改成英文输出 |
| 想看答案 | `答案/` 文件夹里有。建议卡住超过 10 分钟、或者已经通过以后再看 |
| 环01 题1 文件头写的是「基础.c」 | 就是现在的讲义（文件改了名，没改你写过的题1，免得 pull 时冲突） |
| 双击 讲义.html 打开是乱码或者空白 | 换 Edge 或 Chrome 打开；还不行告诉 AI |

## 六、回访时怎么用

C 回访里如果某题是 **L2**：打开那道题，把函数体删掉重写，再运行 `ringNN_test`，报那一行结果。

## 八、部署讲义网站（静态网站）

`site/` 文件夹是整套讲义的静态网站：`index.html` 是目录页，`r01.html`–`r13.html` 是 13 环讲义，样式和脚本都写在页面里，没有别的依赖。

- **GitHub Pages**：仓库 Settings → Pages → Source 选「GitHub Actions」。仓库里的 `.github/workflows/pages.yml` 会在每次推送到 main 后自动发布 `site/`。
- **其他静态托管**（Netlify、Vercel、Cloudflare Pages、自己的服务器）：发布目录填 `site`，不需要构建命令。
- **本地预览**：`python3 -m http.server -d site 8000`，浏览器打开 http://localhost:8000 。

改了讲义源文件（`公共/讲义/环NN.txt` 等）以后重新生成：
```
python3 公共/讲义/check_progs.py      # 编译运行全部完整程序，更新运行结果（需要 gcc）
python3 公共/讲义/build.py            # 生成仓库里的 环NN/讲义.html 和 讲义目录.html
python3 公共/讲义/build.py --site site  # 生成部署用的 site/
```
